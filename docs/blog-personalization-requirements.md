## 1. 项目定位

将现有 Aemeath 博客改造为一个长期维护的中文个人知识站点。保留现有布局、页面结构和主要交互，替换全部原站身份和内容，使其成为以学习沉淀为核心、项目记录为闭环、资源推荐为补充，同时保留人文表达的个人博客。

站点不是教程搬运站，也不是依赖评论、流量统计或第三方平台运营的内容平台。它的首要使用者是站长本人，其次是希望跟着复现、查阅和获得资源线索的读者。

## 3. 目标、非目标与成功标准

### 3.1 三个必达目标

1. 学习可沉淀：学习笔记能够持续积累代码、公式、复现步骤、结果和局限，逐步形成个人 AI 知识库。
2. 项目有闭环：项目文章必须写清背景、方案、踩坑、结果和可复用资源。
3. 风格不分裂：技术内容保持准确、克制，同时保留“载尘望星”的人文视角，不写成冷冰冰的教程汇编。

### 3.2 明确不要

1. 不要自动音乐、无关插件和干扰阅读的装饰。
2. 不要纯复制教程、洗稿、无个人验证或没有自己思考的内容。
3. 不要强制登录评论、复杂图床和单一托管平台绑定。
4. 不追热点，不为流量或算法改变写作方向。

### 3.3 完成标准

1. 数据自主：源文件可本地保存、可迁移，后续可通过 GitHub 备份，部署平台不是唯一数据来源。
2. 表达自由：站点结构服务于长期写作，不依赖评论、访问量或外部内容平台才能成立。
3. 心理归宿：页面安静、清晰、稳定，能够承载多年持续写作，而不是一次性的展示页。

## 4. 内容结构

### 4.1 内容优先级

1. 学习记录。
2. 资源推荐。
3. 个人项目。
4. 随笔与人文表达，目标占比约 10%。

### 4.2 学习笔记

系统字段 `title` 和 `date` 必填，用户指定字段 `topic` 必填。其余字段按笔记类型使用，没有内容时不展示空字段。

推荐字段及默认规则：

| 字段 | 规则 |
| --- | --- |
| 状态 | 可选，默认值为“整理中” |
| 日期 | 必填 |
| 主题 | 必填 |
| 来源 | 可选，论文、课程、文档或实践来源 |
| 要解决的问题 | 默认必填 |
| 核心概念 | 默认必填 |
| 代码 | 有代码时必填 |
| 公式 | 有公式时必填 |
| 复现步骤 | 有实验或工程过程时必填 |
| 结果 | 有验证过程时必填 |
| 局限 | 可选，但重要结论应说明边界 |
| 相关笔记 | 可选 |
| 标签 | 可选，用于检索和串联知识 |

学习分类固定为：

- AI基础
- 机器学习
- 深度学习
- LLM与Agent
- 论文精读
- 工程实践
- 数学基础

### 4.3 项目记录

项目文章默认包含以下正文结构：

1. 背景
2. 目标
3. 方案
4. 架构
5. 实现过程
6. 踩坑
7. 结果
8. 可复用资源
9. 后续计划

其中背景、目标、方案、踩坑、结果和可复用资源为项目闭环的最低要求。性能数据、成本、开源地址和演示地址按项目实际情况增加。

### 4.4 资源推荐

资源使用独立页面维护，不混在普通文章流中。每条资源至少包含：

- 名称
- 用途
- 推荐理由
- 适用人群
- 替代方案
- 标签
- 原始链接

推荐理由必须是个人使用后的判断，不写无法验证的营销话术。失效资源应标记或移除。

### 4.5 随笔

设立独立“随笔”分类，用于观察、思考、生活和非技术内容。随笔可以保留人文视角，但不能以抒情替代技术文章中的事实、验证和复现过程。

## 5. 原有内容处理

“old content直接下线、不单独备份”的最终执行规则如下：

1. 原站文章、图片、配置和不再使用的数据直接从公开内容与项目中移除，不建立归档目录、压缩包或其他备份副本。
2. 如需追溯历史内容，只依赖 Git 历史；Git 历史不是站点运行依赖，也不再对外公开。
3. 实施完成后，站点的公开内容集合为空，只保留新站身份、页面骨架、模板和空状态。
4. 后续新文章必须由站长按新的学习、项目或随笔规范重新撰写，不能把原站正文原样恢复后继续发布。
5. 文章模板示例只作为本地模板存在，不放入公开内容集合，也不自动成为公开文章。

## 7. 视觉与交互

视觉范围采用方案 A：保留当前壁纸、卡片体系和主要动效，只替换品牌、头像、Logo、文字和身份信息。

具体要求：

1. 保留现有页面布局、侧边栏、卡片、主题色机制、明暗模式和主要过渡动画。
2. 替换首页主标题、副标题、作者信息、站点元数据、favicon、Logo 和分享图。
3. 关闭音乐播放器和背景视频自动播放。

5. 当前不补交新的头图、默认封面和相册素材，后续单独迭代。
6. 桌面端和移动端均需保证正文可读、控件可操作、文本不重叠。
7. 动效不能成为理解内容或完成导航的必要条件。

- RSS

所有原站统计 ID、评论地址、API UID、分享 ID、回放域名、社交账号和邮箱必须从源码、配置、HTML、JSON 数据、生成元数据和静态输出中清除。

## 9. 版权与许可

1. 保留项目 `LICENSE`、页脚版权声明和依法必须保留的第三方许可声明。
2. 页脚署名改为 `© 2026 尘之泪`，不保留原站作者身份文案。
3. 原站文章正文不再随改造后的站点上线，也不因代码仓库采用 MIT License 而自动获得转载授权。
4. 新文章页继续显示版权声明，但署名、来源和新站许可范围必须与 `载尘望星` 一致。

## 10. 部署、域名与备份

1. 当前没有自定义域名，不硬编码 `rainzt.cn`；站点地址默认使用 Vercel 域名，并支持环境变量覆盖。
2. 保持 Astro 静态构建能力，部署目标是 Vercel，但构建产物仍需可迁移到其他静态托管平台。
3. 当前没有 GitHub 仓库信息。实施阶段先保证本地源码完整；新站源码的 GitHub 备份在仓库创建后补上，旧文章不做额外交付备份。
4. 部署前必须通过类型检查、生产构建、搜索索引和本地预览验证。
5. 不依赖评论服务、数据库或持久化服务器才能运行核心页面。
